# Express + Passport Auth Server

Сервер на Node.js/Express з авторизацією через **Passport** (локальна стратегія email/пароль), збереженням сесій через `express-session`, захищеним маршрутом `/protected`, заготовкою під OAuth (Google), функціональністю відновлення забутого пароля через електронну пошту, а також інтеграцією з **MongoDB Atlas** через **Mongoose** і маршрутом читання даних `/items`, що відображає їх на сторінці сервера.

Усі вихідні файли проєкту знаходяться в директорії `src/`; у корені залишені лише конфігураційні/проєктні файли (`package.json`, `.env.example`, `.gitignore`, `README.md`).

## Структура проєкту

```
.
├── package.json
├── jest.config.js
├── .env.example
├── .gitignore
├── README.md
└── src/
    ├── server.js                  # Точка входу: завантажує .env і запускає сервер
    ├── app.js                     # Збірка Express-застосунку: middleware, сесії, passport, маршрути
    ├── config/
    │   ├── session.js             # Налаштування express-session (httpOnly, secure, cookie)
    │   ├── passport.js            # Стратегії Passport: local + Google OAuth2, serialize/deserialize
    │   └── db.js                  # Підключення до MongoDB Atlas через Mongoose (connectDB/disconnectDB)
    ├── controllers/
    │   └── authController.js      # Логіка register/login/logout/forgot-password/reset-password
    ├── middlewares/
    │   └── ensureAuthenticated.js # Мідлвар перевірки валідної сесії перед доступом до /protected, /items (POST)
    ├── models/
    │   ├── User.js                # In-memory сховище користувачів (bcrypt-хешування, reset-токени)
    │   └── Item.js                # Mongoose-схема документів колекції `items` у MongoDB Atlas
    ├── routes/
    │   ├── auth.js                # /auth/* маршрути
    │   ├── protected.js           # /protected маршрут
    │   └── items.js                # /items маршрути: читання з MongoDB (JSON + HTML-сторінка)
    ├── utils/
    │   └── mailer.js              # Надсилання email для відновлення пароля (nodemailer)
    └── tests/
        ├── auth.test.js           # Тести register/login/logout/protected/me
        ├── password-reset.test.js # Тести forgot-password/reset-password
        └── items.test.js          # Тести читання/створення даних у MongoDB (/items)
```

> `jest.config.js` у корені — це конфігураційний файл інструменту тестування (аналог `package.json`), а не вихідний код застосунку, тому він за межами `src/`; усі файли з реальною логікою тестів лежать у `src/tests/`.

> **Примітка щодо зберігання даних:** для простоти запуску "з коробки" користувачі зберігаються в пам'яті процесу (`src/models/User.js`). Для продакшн-використання замініть реалізацію `UserStore` на звернення до реальної БД (MongoDB/PostgreSQL тощо), зберігши ті самі методи (`create`, `findByEmail`, `findById`, `setResetToken`, ...), — решта застосунку зміниться мінімально. Так само `express-session` використовує стандартний `MemoryStore`, придатний лише для розробки; для продакшну підключіть персистентне сховище сесій (наприклад `connect-redis`, `connect-mongo`).

## Встановлення та запуск

### Вимоги
- Node.js >= 18
- npm

### Кроки

1. Встановити залежності:
   ```bash
   npm install
   ```

2. Створити файл `.env` на основі прикладу та за потреби відредагувати значення:
   ```bash
   cp .env .env
   ```

   Ключові змінні:
   | Змінна | Опис |
   |---|---|
   | `PORT` | Порт, на якому запускається сервер (за замовчуванням `3000`) |
   | `SESSION_SECRET` | Секрет для підпису cookie сесії — обов'язково змінити в продакшні |
   | `USE_SECURE_COOKIES` | `true`, якщо застосунок працює за HTTPS (додає прапорець `secure` до cookie сесії) |
   | `RESET_TOKEN_TTL_MINUTES` | Термін дії токена відновлення пароля в хвилинах |
   | `APP_BASE_URL` | Базовий URL, що використовується для формування посилання відновлення пароля |
   | `SMTP_*`, `MAIL_FROM` | Налаштування SMTP для надсилання email. Якщо не задані — лист просто виводиться в консоль (зручно для локальної розробки/тестування) |
   | `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` / `GOOGLE_CALLBACK_URL` | Опційні — якщо задані, активується стратегія Google OAuth2 |
   | `MONGODB_URI` | **Обов'язкова.** Рядок підключення до MongoDB Atlas (див. розділ нижче) |

3. Налаштувати MongoDB Atlas — див. розділ «Підключення до MongoDB Atlas» нижче — і вписати отриманий рядок підключення у `MONGODB_URI` в `.env`.

4. Запустити сервер:
   ```bash
   npm start
   ```
   або в режимі розробки з автоперезапуском (`nodemon`):
   ```bash
   npm run dev
   ```
   Якщо `MONGODB_URI` не задано або не вдається підключитися, сервер виведе зрозуміле повідомлення про помилку та завершить роботу (`process.exit(1)`), не запускаючи прослуховування порту.

5. Сервер буде доступний за адресою `http://localhost:3000`.

## Підключення до MongoDB Atlas

1. Зареєструйтеся/увійдіть на [cloud.mongodb.com](https://cloud.mongodb.com) та створіть безкоштовний кластер (M0).
2. **Database Access** → створіть користувача бази даних (логін + пароль, роль `Read and write to any database` достатньо для цього проєкту).
3. **Network Access** → додайте IP-адресу, з якої підключатиметеся (для локальної розробки можна тимчасово дозволити `0.0.0.0/0` — "Allow access from anywhere"; для продакшну обмежте список конкретними адресами).
4. На сторінці кластера натисніть **Connect → Drivers**, оберіть Node.js і скопіюйте рядок підключення вигляду:
   ```
   mongodb+srv://<username>:<password>@<cluster-url>/<dbname>?retryWrites=true&w=majority
   ```
5. Підставте власні `<username>`, `<password>` та назву бази `<dbname>` (наприклад, `express-passport-auth`) і вставте результат у `.env` як значення `MONGODB_URI`.
6. Підключення встановлюється через `mongoose.connect(...)` у `src/config/db.js`, яке викликається з `src/server.js` **до** запуску `app.listen(...)`, — тобто сервер не почне приймати запити, поки з'єднання з Atlas не буде встановлено.
7. Схема документів визначена в `src/models/Item.js` (колекція `items`, поля `title`, `description`, автоматичні `createdAt`/`updatedAt`). За потреби замініть/розширте поля під власну предметну область — решта коду (маршрут читання) не зміниться.

### Як додати дані для перегляду

Маршрут читання (`GET /items`) просто читає наявні документи — щоб було що показувати, додайте запис одним із способів:

- через API (потребує авторизованої сесії — спершу `POST /auth/register` або `/auth/login`):
  ```bash
  curl -b cookies.txt -X POST http://localhost:3000/items \
    -H "Content-Type: application/json" \
    -d '{"title":"Перший запис","description":"Дані з MongoDB Atlas"}'
  ```
- або вручну через інтерфейс **Atlas → Browse Collections** у вашій базі/колекції `items`.

## Тестування

Проєкт містить інтеграційні тести (Jest + Supertest), що перевіряють усі ключові сценарії одразу:

- реєстрацію (успіх, дублікат email, закороткий пароль);
- вхід (успіх, невірний пароль, неіснуючий email);
- доступ до `/protected` з валідною сесією та відмову без неї;
- `GET /auth/me` до і після виходу;
- вихід (`/auth/logout`) та знищення сесії;
- відновлення пароля: надсилання листа (mailer замокано — реальний SMTP не потрібен), захист від перебору email, невалідний/одноразовий токен, вхід зі старим і новим паролем;
- читання даних з MongoDB (`GET /items`): порожня колекція, кілька документів, обробка помилки БД (500);
- HTML-сторінка (`GET /items/page`): коректний рендер даних, екранування HTML (захист від XSS у `title`/`description`), повідомлення про порожню колекцію;
- створення запису (`POST /items`): відмова без авторизації (401), відмова без `title` (400), успішне створення авторизованим користувачем (201).

Тести не запускають сервер на реальному порту — вони звертаються напряму до Express-застосунку (`src/app.js`) через `supertest`, тому мережа не потрібна. Тести `src/tests/items.test.js` **мокають Mongoose-модель `Item`** (`jest.mock('../models/Item')`), тож для їх запуску не потрібні ні реальний кластер MongoDB Atlas, ні `MONGODB_URI` в `.env`, ні доступ до мережі — увесь набір тестів виконується повністю офлайн. Сам код маршруту (`src/routes/items.js`) при цьому не змінюється — відрізняється лише джерело даних за `Item.find()`/`Item.create()` (мок у тестах проти реального MongoDB Atlas під час звичайного запуску сервера).

Запустити всі тести однією командою:

```bash
npm install   # якщо ще не виконано
npm test
```

Файли тестів знаходяться в `src/tests/` (`auth.test.js`, `password-reset.test.js`, `items.test.js`), конфігурація Jest — у `jest.config.js` у корені проєкту.

## Опис маршрутів

Усі маршрути (окрім зазначеного) приймають/повертають `application/json`.

### `GET /`
Коротка довідка про сервер та список доступних маршрутів.

### `POST /auth/register`
Реєстрація нового користувача.

- **Тіло запиту:**
  ```json
  { "email": "user@example.com", "password": "secret123", "displayName": "Ім'я (опційно)" }
  ```
- **Поведінка:** хешує пароль через bcrypt, створює користувача, одразу автоматично авторизує (`req.login`) і створює сесію.
- **Відповіді:** `201` з об'єктом користувача; `409` якщо email вже зайнято; `400` при відсутніх/некоректних полях.

### `POST /auth/login`
Вхід через стратегію Passport `local`.

- **Тіло запиту:**
  ```json
  { "email": "user@example.com", "password": "secret123" }
  ```
- **Поведінка:** Passport перевіряє email/пароль; за успіху створюється сесія, а ідентифікатор сесії зберігається у cookie `sid` (`httpOnly`, за потреби `secure`).
- **Відповіді:** `200` з об'єктом користувача; `401` при невірних облікових даних.

### `POST /auth/logout`
Завершення сесії поточного користувача (`req.logout`) та її знищення на сервері, з очищенням cookie `sid`.

- **Відповідь:** `200` з повідомленням про успішний вихід.

### `GET /auth/me`
Повертає поточного авторизованого користувача (або `null`, якщо сесія відсутня/невалідна). Зручно для перевірки стану авторизації на фронтенді.

### `POST /auth/forgot-password`
Запит на відновлення пароля.

- **Тіло запиту:** `{ "email": "user@example.com" }`
- **Поведінка:** якщо користувача з таким email знайдено — генерується одноразовий токен (зберігається лише його хеш, з терміном дії `RESET_TOKEN_TTL_MINUTES`), і на пошту надсилається лист з посиланням виду `APP_BASE_URL/auth/reset-password?token=...`. Відповідь однакова незалежно від того, існує email чи ні — це запобігає розкриттю списку зареєстрованих email.

### `POST /auth/reset-password`
Встановлення нового пароля за токеном з листа.

- **Тіло запиту:** `{ "token": "...", "password": "newSecret123" }`
- **Поведінка:** перевіряє токен (хеш і термін дії), встановлює новий пароль, інвалідовує токен.
- **Відповіді:** `200` при успіху; `400` якщо токен недійсний/прострочений або пароль закороткий.

### `GET /auth/google`
Ініціює вхід через Google OAuth2 (активний лише якщо в `.env` задані `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`). Перенаправляє користувача на сторінку згоди Google.

### `GET /auth/google/callback`
Callback-маршрут, на який Google повертає користувача після авторизації. При успіху створюється (або знаходиться наявний) локальний обліковий запис за email з профілю Google, створюється сесія, і користувач перенаправляється на `/protected`. При невдачі — редірект на `/auth/google/failure`.

### `GET /protected`
Захищений маршрут. Доступ надається лише за наявності валідної авторизованої сесії — це перевіряє мідлвар `ensureAuthenticated` (використовує `req.isAuthenticated()` від Passport) до виконання обробника маршруту.

- **Відповіді:** `200` з даними користувача, якщо сесія валідна; `401`, якщо користувач не авторизований.

### `GET /items`
**Новий маршрут читання даних з MongoDB Atlas.** Виконує `Item.find().sort({ createdAt: -1 }).lean()` через Mongoose і повертає документи колекції `items` у форматі JSON — для використання клієнтським кодом/API-споживачами.

- **Відповідь:** `200 { "items": [ { "_id", "title", "description", "createdAt", "updatedAt" }, ... ] }`, відсортовано від найновіших до найстаріших; `500` при помилці БД.

### `GET /items/page`
Та сама операція читання з MongoDB, але результат відображається як готова HTML-сторінка (сервер сам формує і повертає розмітку — саме це і є «відображення даних на сторінці сервера» із завдання). Значення `title`/`description` екрануються перед вставкою в HTML для захисту від XSS.

- **Відповідь:** `200` з `Content-Type: text/html`, список записів або повідомлення «Даних поки немає», якщо колекція порожня.

### `POST /items`
Допоміжний захищений маршрут для наповнення колекції даними (щоб було що читати/показувати) — не є вимогою завдання сам по собі, але потрібен для наскрізної перевірки читання.

- **Тіло запиту:** `{ "title": "Назва", "description": "Опис (опційно)" }`
- **Поведінка:** потребує авторизованої сесії (та сама перевірка `ensureAuthenticated`, що й у `/protected`); створює документ у MongoDB через `Item.create(...)`.
- **Відповіді:** `201` зі створеним документом; `400` якщо відсутній `title`; `401` без авторизованої сесії.

## Приклад сценарію роботи (curl)

```bash
# Реєстрація (зберігає cookie сесії у файл cookies.txt)
curl -c cookies.txt -X POST http://localhost:3000/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"user@example.com","password":"secret123"}'

# Доступ до захищеного маршруту з тією ж сесією
curl -b cookies.txt http://localhost:3000/protected

# Вихід
curl -b cookies.txt -X POST http://localhost:3000/auth/logout
```

```bash
# Додавання запису в MongoDB (потребує авторизованої сесії, cookies.txt з прикладу вище)
curl -b cookies.txt -X POST http://localhost:3000/items \
  -H "Content-Type: application/json" \
  -d '{"title":"Перший запис","description":"Приклад даних з MongoDB Atlas"}'

# Читання даних: JSON
curl http://localhost:3000/items

# Читання даних: HTML-сторінка — відкрийте в браузері
# http://localhost:3000/items/page
```

## Безпека сесій

- Cookie сесії (`sid`) встановлюється з прапорцем `httpOnly`, що унеможливлює доступ до неї з клієнтського JavaScript.
- Прапорець `secure` вмикається через `USE_SECURE_COOKIES=true` — застосовуйте це в продакшні за HTTPS, щоб cookie передавалася лише захищеним з'єднанням.
- `sameSite: 'lax'` додає базовий захист від CSRF для типового сценарію автентифікації на основі сесій.

## Подальший розвиток

- Підключення додаткових стратегій Passport (Facebook, GitHub тощо) — за тим самим патерном, що й `GoogleStrategy` у `src/config/passport.js`.
- Перенесення in-memory `UserStore` (зараз у `src/models/User.js`) на MongoDB Atlas через Mongoose — за тим самим патерном, що й `Item.js`/`src/config/db.js`, для персистентності користувачів між перезапусками сервера.
- Заміна `MemoryStore` сесій на персистентне сховище (наприклад `connect-mongo`, що зберігатиме сесії в тій самій базі MongoDB Atlas) для продакшн-розгортання.
- Додавання CRUD-операцій (Update/Delete) для колекції `items`, пагінації та фільтрації у `GET /items`.
- Додавання валідації вхідних даних (наприклад, через `zod`/`joi`) та rate-limiting на маршрутах `/auth/login` і `/auth/forgot-password`.
